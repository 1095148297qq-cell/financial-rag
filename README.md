## 财报问答结论

### 10道评测题

1. 贵州茅台 2024、2025 年营业收入和归母净利润分别是多少？请按亿元列出并给出两份年报出处。
2. 五粮液 2025 年营业收入、归母净利润及其同比分别是多少？
3. 泸州老窖 2025 年经营活动现金流量净额和归母净利润是多少？前者约占后者多少百分比？ **【曾失败】** 漏召回归母净利润，比例无法计算。
4. 对照洋河股份 2024 和 2025 年年报，经营活动现金流量净额分别是多少？是否由正转负？
5. 古井贡酒 2025 年加权平均净资产收益率是多少？较 2024 年下降多少个百分点？
6. 山西汾酒 2025 年营业收入和归母净利润同比增幅分别是多少？两者相差多少个百分点？
7. 对照舍得酒业 2024 和 2025 年年报，两年经营活动现金流量净额是多少？2025 年仍为负吗？ **【曾失败】** 把现金净流出称为亏损，概念错误。
8. 水井坊 2025 年年报“可能面对的风险”列出哪两类风险？每类概括一项应对措施。
9. **【跨公司全景题】** 在本库 12 家白酒公司中，按 2025 年营业收入由高到低完整排序，列出各家金额（亿元）。覆盖不足时说明缺失公司。 **【曾失败】** 仅确认4家公司营收，排序未完成。
10. **【跨公司全景题】** 逐一列出本库 12 家公司的 2025 年营业收入同比增幅；共有几家增长，分别是谁？使用 2025 年年报中披露的 2024 年可比数据，列明证据覆盖。

第9、10题均要求覆盖本库全部12家公司；其余为单公司查询、跨年比较、计算或解释题。第3、7、9题标注“曾失败”，对应保留的真实失败记录；同题另有成功回答，不表示每次都失败。

公司、年度和指标明确的事实查询表现较好，例如茅台两年营收与归母净利润、洋河经营现金流由正转负，以及跨12家公司的营收排序。这些问题的数据相对集中，容易定位到原文表格并给出出处。

失败主要出现在证据不完整、口径混淆与计算环节：现金流比例题曾因漏召回归母净利润而无法完成；合并与母公司比较曾漏掉目标报表行；渠道、经销商与合同负债的多事项题只完成部分查询；直销占比在金额已召回时仍将50.09%算成50.18%；附注题无法凭局部片段确认最大调整项。这些均来自保留的实际回答，不将诚实说明证据不足与编造数字混为一谈。

同一批财报，年度指标查询、跨年变化和跨公司比较适合建库，因为事实会更新、答案需要可追溯出处。改进优先级是按子问题与报表口径分别检索、补全表格、核对跨公司覆盖，并用程序验证金额换算、比例与排序。少量题目答对不能代表总体准确率；本项目未做微调，不据此比较微调效果。

建议 Python 3.11。首次下载模型和处理 4,408 页报告需要时间；下载、提取、向量计算均有本地缓存。

## 新版页面的默认行为（2026-10-12）

新版网页默认连接全部12家公司、2024及2025年度的24份年报，固定使用向量 + BM25。页面已移除公司、年度、索引及增强开关。直接用自然语言提问，系统识别简称（茅台、汾酒、老窖等）、营收及相对年份；“去年”按后端当前日期解释，“最新”指库内最新的2025年度并明确提示。问题未指定范围时在全库检索；指定公司/年度时自动聚焦相关材料。跨公司排序会逐公司召回，不能把召回覆盖视为答题正确率。

开放问题使用向量与BM25检索，不依赖10道示例题或答案关键词白名单。“只想核对……”等最终指令可覆盖前文背景公司；相关页面表格补全与母公司/合并现金流原文行补召回，用于减少范围及口径混淆。规则无法穷尽所有自然表达，证据缺失时仍应说明不足。超出2024、2025年度的问题提示材料范围，生成模式不调用模型。

## 方法

- PDF 原始文本逐页提取；用严格线段识别还原表格，保留列名、列号、单元格值及原始行。合并单元格留空，不猜测数值。同行不拆开，相邻行按约 800 字打包。叙述按 800 字、120 字重叠切分。
- 每块含公司、股票代码、年报年度、章节、PDF 页码及块 ID。页码是 PDF 文件从 1 开始的物理页码。
- 同页多个章节并列标注，后续页继承最后一个标题。原始 v3 实验曾保留构建时 `embedding_text` 快照；新 v4 库使用当前提取内容重新计算向量，并以模型名称和文本内容指纹隔离缓存，避免复用旧向量。
- v4 修复续表首行金额误作表头：识别多行表头；只有相邻页、列数、表格位置与财务报表标题对应时继承年度列。不能确认的表头明确标记“未识别列”，保留首行及原始值，不猜测口径。该修复不等于全库逐单元格校验。
- 本地 `BAAI/bge-small-zh-v1.5` 512 维向量，余弦相似度；jieba 分词 + BM25；RRF 融合两类召回。
- 新版网页按问题自动识别公司和年度，固定混合检索；跨公司比较逐公司召回。历史实验保留显式筛选。覆盖公司数代表有块被召回，不代表答案必然完整、正确。
- 默认启用混合检索增强：展开“归母”等术语、按公司及年度分别召回，单公司题补全最相关页面上的其他块。对照实验另保留未增强的三种索引模式，并分别记录增强效果。
- v4 增强检索额外按表格的年度列、指标行名及前25页位置识别年度指标表，优先补入相关原文行。该规则不读取参考答案文件；不能确认年度列时仍依赖常规检索，可能遗漏或发生口径错误。
- GPT 仅根据召回证据作答，每项事实标引用编号，可展开原文并跳转官方 PDF。

## 复现评测

先下载原始年报并完成提取和索引，再运行：

```powershell
python -m financial_rag.prepare_evaluation
python -m financial_rag.evaluate --modes hybrid_expanded
```

准备脚本从原始PDF提取参考指标；评测实际调用模型，消耗运行者的API余额或账户计划额度。当前10题包含2道跨12家公司的全景题。生成结果写入`output/evaluation_v4/`，包括实际回答、召回块和自动诊断；自动诊断不能替代人工复核。

已有结果重跑前请另存备份，并重新核对金额、单位、年度、正负号、计算、排序及引用。固定题用于开发调试，不能外推总体准确率。`deliver_v4`仅用于本机已完成人工复核的记录，检查证据指纹，不会给新回答自动评分；新克隆环境缺少复核文件时不能直接运行它。

控制调用次数可指定 `--question-ids Q02 Q03`。`MAX_MODEL_CALLS`限制本地累计调用次数（含失败请求），请求不自动重试；次数上限不等于货币预算。向量计算使用本地模型。

不调用模型的检查：

```powershell
python -m unittest discover -s tests -v
python -m financial_rag.verify_web
python -m financial_rag.check_public_files
```

`verify_web`需要本机后端及索引；单元测试使用临时数据，不依赖作业附件。安全扫描结果也只保存在本机`output/`。

### 同索引、同模型的挑战对照

2026-10-10新增4道挑战题，覆盖合并/母公司现金流、多事项查询、干扰公司名称、现金流调节附注。原10题继续作为开发回归集，没有替换或改写。挑战题先核对原始PDF，再冻结题目、参考页、索引文件及召回证据的SHA256；使用同一v4索引和`gpt-6-luna`，普通混合与现有增强各生成一次，共8次现有授权调用。

完整答对为普通混合2/4、增强混合0/4。两种方式都漏掉多事项题的合同负债；增强遗漏母公司目标行及附注调整项，并在正确召回金额后将50.09%算成50.18%。普通混合在附注题给出正确数值，但明确无法确认完整排名，按冻结标准记为部分完成。诚实拒答与编造数字分别记录。四题、每格单次生成、上下文预算不同，不能据此推断总体准确率或计算错误的因果关系。

这些结果及完整原答、召回块、评分和参考页仅在本机`output/challenge/`与`交付材料/challenge/`。不上传参考答案或评测附件。新克隆者可自行建立符合下列字段的`output/challenge/questions.json`（4题）：`id`、`question`、`type`、`expected_companies`、`expected_values`、`criteria`、`sources`（每项含`file`与`pages`）。先自行核对参考页，再运行：

```powershell
# prepare仅做本地检索，不生成答案；实验固定为现有本地授权，不使用API key
python -m financial_rag.challenge_evaluate prepare --model gpt-6-luna
# run最多8次回答，验证冻结输入与模型/授权；已有开始/失败记录均不自动重试
python -m financial_rag.challenge_evaluate run
```

调用前必须具备该模型的有效本地授权；模型或授权方式变化时请求前停止。`challenge_report`只发布已人工复核且证据指纹匹配的本机报告，不能为新结果自动评分。`review_checks`提供声明精度的百分比核对和实际引用页覆盖辅助检查；引用到某页仍不代表对应事实受支持，原10题自动诊断保持原样。

历史实验的一页结论为`pdf/conclusion.pdf`，同时包含原10题与挑战结果；更新前版本另存`pdf/conclusion_v4_before_challenge.pdf`，仅作历史存档。`challenge/report.html`是原答的离线复核页面，`screenshots/challenge_C03_comparison.png`是该页面截图，作为原问答页面截图的补充。再次运行旧`deliver_v4`会生成仅含回归结果的旧式结论；本次最终提交使用`交付材料/最终提交/方向A_问答结论.pdf`，聚焦实际问答表现与失败原因；历史报告保持原样。

该历史实验的下一步建议是验证子问题分别检索、按报表口径与附注补全相关表、覆盖检查和确定性计算。当时尚未据这4题调整检索；2026-10-12后续规则变化及验证见前文，挑战评分没有重跑。
